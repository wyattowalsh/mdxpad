MDXPad follows Electron's multi-process architecture with four distinct layers. Each layer has a clearly defined responsibility and a restricted import surface — code from one layer cannot directly call into another except through the sanctioned IPC bridge.

## IPC Flow

## Main Process

The Main process runs in Node.js with full system access. It owns all privileged operations: file system I/O, native OS integration, and service orchestration.

**Entry point**: `src/main/index.ts`

**Responsibilities:**
- Application lifecycle (ready, window management, quit)
- Native macOS menus (`menu.ts`)
- File system operations via `FileService`
- IPC handler registration (`src/main/ipc/`)
- All backend services: AI, collaboration, export, git, search, plugins, version history, notifications

**IPC handlers** (`src/main/ipc/`): Every `ipcMain.handle` call validates the incoming payload with the corresponding Zod request schema and validates the outgoing response with the response schema before returning. Sender origin is validated by `ipc-sender-authorization.ts`.

## Preload Script

The Preload script runs in the renderer's context but with Node.js access still available. It constructs the `window.mdxpad` API surface that the renderer uses to communicate with the main process.

**Entry point**: `src/preload/index.ts`

**Key exports:**
- `window.mdxpad` — The complete typed API object
- `validatedInvoke` — Zod-validated IPC invoke helper

```typescript
// src/preload/validated-invoke.ts
export async function validatedInvoke<T>(
  channel: string,
  payload: unknown,
  schema: z.ZodType<T>
): Promise<T> {
  const raw = await ipcRenderer.invoke(channel, payload);
  return schema.parse(raw); // throws ZodError on invalid response
}
```

<Callout type="info">
  Context isolation is enabled (`contextIsolation: true`) and Node integration is disabled (`nodeIntegration: false`) in the renderer. The Preload script is the only path from renderer to system APIs.
</Callout>

## Renderer Process

The Renderer process is a standard browser context running the React application. It has no direct Node.js or file system access — everything goes through `window.mdxpad`.

**Entry point**: `src/renderer/main.tsx`

**Responsibilities:**
- React 19 application shell (`App.tsx`)
- CodeMirror 6 editor with 14 custom extensions
- ProseMirror WYSIWYG editor
- MDX preview with Web Worker compilation pool
- Zustand + Immer state management (25+ stores)
- Radix UI + Tailwind CSS components

## Shared Layer

The Shared layer contains code that is imported by both the Main and Preload processes. It must contain no platform-specific code — everything here must be importable in either Node.js or a browser context.

**Location**: `src/shared/`

**Contents:**
- `contracts/` — Zod schemas for every IPC channel (request + response)
- `types/` — TypeScript type definitions
- `lib/` — Utilities: `atomic-write.ts`, `checksum.ts`, `error-utils.ts`, `result.ts`
- `security/` — Origin validator, rate limiter, CSP nonce, sanitizer
- `ai/` — AI-related shared schemas and constants
