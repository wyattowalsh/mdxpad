## Exporter Interface

All format exporters implement a common `Exporter` interface, making them pluggable and testable in isolation:

```typescript
interface Exporter {
  readonly format: string;
  readonly label: string;
  readonly extensions: string[];
  export(content: string, options: ExportOptions): Promise<ExportResult>;
}
```

## PDF Export

Uses Electron's `printToPDF` API. The document content is compiled to HTML using the MDX pipeline first, then fed to `printToPDF` to produce a PDF that matches the preview rendering.

## DOCX Export

Uses the `docx` npm package (`^9.x`) to generate Word documents. Supported elements:

- Headings H1–H6 (mapped to Word heading styles)
- Paragraphs with inline formatting (bold, italic, code)
- Fenced code blocks
- Ordered and unordered lists

## EPUB Export

Uses `epub-gen-memory` for in-memory e-book generation without intermediate disk writes. Features:

- Title and author pulled from YAML frontmatter
- Automatic chapter splitting
- Basic inline formatting

## LaTeX Export

Converts MDX content to LaTeX markup:

- Document class and package declarations
- Heading commands: `\section`, `\subsection`, `\subsubsection`, etc.
- Code listings via `listings` or `verbatim`
- Inline formatting: `\textbf`, `\textit`, `\texttt`

## Pandoc Bridge

The `PandocRawExporter` integrates with Pandoc when it is installed on the system.

### Detection

```typescript
import { detectPandoc } from './pandoc-detector';

const result = await detectPandoc();
// { available: boolean, version?: string, path?: string }
```

`pandoc-detector.ts` checks for Pandoc availability at runtime. If Pandoc is not found, the Pandoc export option is hidden in the UI.

### Custom Formats

The `PandocRawExporter` passes content through the Pandoc CLI with user-specified output format flags, enabling any format Pandoc supports: reStructuredText, AsciiDoc, ODT, Textile, etc.

## Built-in Formats

The `ExportService` (`export-service.ts`) handles HTML, Markdown, and MDX exports directly:

- **HTML**: Full HTML page with embedded CSS
- **Markdown**: Strips MDX-specific syntax, outputs plain Markdown
- **MDX**: Identity export — copies the source with normalized line endings

## Export Orchestration

The `ExportOrchestrator` (`export-orchestrator.ts`) manages export jobs with a full lifecycle:

- **Job lifecycle**: create, get, list, cancel, update-status
- **Preset management**: create, get, list, update, delete named export presets
- **Progress tracking**: real-time progress updates via IPC events

## CLI Orchestration

The `CLIService` and `CLIEngine` provide command-line export capabilities accessible from the renderer:

```typescript
window.mdxpad.export.cliInvoke({
  command: 'mdxpad-export',
  args: ['--format', 'pdf', '--output', '/path/to/output.pdf'],
})
```

## llms.txt Generation

<Callout type="info">
  `llms.txt` is a community convention for making documentation accessible to AI language models. See [llmstxt.org](https://llmstxt.org) for the specification.
</Callout>

The `LlmsGenerator` produces two files from the workspace:

- **`llms.txt`** — Concise index of workspace files with titles and descriptions
- **`llms-full.txt`** — Full content of all workspace files concatenated

```typescript
window.mdxpad.export.llmsGenerate({
  workspacePath: '/path/to/workspace',
  outputDir: '/path/to/output',
})
```

## IPC API

Export features are exposed via `window.mdxpad.export`:

| Method | Description |
|--------|-------------|
| `export.jobLifecycle` | Create, get, list, cancel, and update-status on export jobs |
| `export.presetCrud` | Create, get, list, update, and delete named presets |
| `export.cliInvoke` | Run an export command via the CLI engine |
| `export.llmsGenerate` | Generate `llms.txt` and `llms-full.txt` |

IPC schemas are in `src/shared/contracts/export-schemas.ts` and `src/shared/contracts/export-format-schemas.ts`.
